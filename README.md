# 施工日誌產生器（通用版）— 使用說明

## 這是什麼

把「新案子做成施工日誌」這件事，包成一支可以在您自己電腦上重複執行的 Python 程式。
以後每個新案子，只要準備好該案的 PCCES 匯出檔（詳細價目表/標價清單），跑一行指令，
就會自動產生完整的施工管理活頁簿（日資料庫／預定進度／甘特圖／施工日報 4張分頁），
不需要再回來這個對話請我手動做。

檔案：
- `build_construction_log.py`：主程式，直接執行這支。
- `_report_layout.py`：施工日報版面的邏輯，`build_construction_log.py` 執行時會自動載入，
  兩個檔案要放在同一個資料夾。
- `requirements.txt`：安裝需要的套件清單。

## 安裝（只需要做一次）

1. 安裝 Python 3.9 以上版本（<https://www.python.org/downloads/>），安裝時記得勾選
   「Add python.exe to PATH」。
2. 把這三個檔案放在同一個資料夾。
3. 打開命令提示字元(cmd)，切換到這個資料夾，執行：

   ```
   pip install -r requirements.txt
   ```

   （只需裝一次，之後每個新案都不用再裝。）

## 使用方式

```
python build_construction_log.py "您的PCCES檔案路徑.xls"
```

常用參數（都有預設值，不給也能跑，跑完看畫面上印出的提醒訊息即可）：

| 參數 | 用途 | 預設 |
|---|---|---|
| `--sheet 分頁名稱` | 手動指定要讀哪個分頁 | 自動偵測含「項次/單位/數量/單價」表頭的分頁 |
| `--start-date 2026-09-01` | 開工日期 | 今天（事後也可以直接在Excel B2改，全部日期會自動跟著更新） |
| `--days 200` | 日資料庫要建幾天份（**這是唯一決定天數的地方**，見下方常見問題） | 200天 |
| `--agency "○○政府"` | 主辦機關（PCCES讀不到時手動補） | 自動從檔案抓，抓不到就留空 |
| `--project-name` / `--location` / `--proj-code` | 工程名稱／地點／編號（手動覆寫） | 自動從檔案抓 |
| `--n-mat` / `--n-labor` / `--n-mach` | 材料／工別／機具主檔筆數上限 | 12 / 8 / 8 |
| `--out 檔名.xlsx` | 輸出檔名 | 用工程名稱自動命名 |

範例：

```
python build_construction_log.py "案A_標價清單.xlsx" --start-date 2026-09-01 --out 案A_施工日誌.xlsx
```

執行完會在同資料夾產生：
- `<檔名>.xlsx`：完整6張分頁的活頁簿（日資料庫／預定進度／甘特圖／施工日報／儀表板／
  PCCES來源核對debug用，見下方各分頁說明）。
- `<檔名>_meta.json`：這個案子的結構資訊（工程名稱/工項清單/大項中項範圍等），
  之後如果要用「估驗計價工具」或「變更設計匯入工具」，需要這個檔案。

### 常見問題：「我工期明明設750天，怎麼跑出來只有200天的日期？」

`--days`（預設200）是**唯一**決定「日資料庫」要建幾天份日期列的參數，日資料庫的
「工期(日曆天)」儲存格（D2）也是產生檔案當下**直接抄`--days`的值**寫進去的，兩者
不是互相連動的公式——事後在Excel裡把D2手動改成750，並不會讓日資料庫底下的日期
列表跟著從200列自動變成750列（那張表是產生當下就建好的固定範圍）。

如果您的契約工期是750天，請重新執行、明確加上 `--days 750`：

```
python build_construction_log.py "您的PCCES檔案.xls" --start-date 2026-09-01 --days 750 --out 案A_施工日誌.xlsx
```

## 開發過程中發現並修正的問題（附驗證方式）

在把邏輯通用化的過程中，我用您現有案子的真實 PCCES 檔案（`pcces.xls`）做回歸測試，
發現並修正了兩個問題：

1. **大項/中項偵測邏輯的根本限制**：舊版程式（`build_v4.py`）用「壹貳參肆伍…」
   在資料表裡的欄位型態（是否為純標題列）判斷大項邊界，導致您案子裡的「貳、委託
   技術服務費」「參、工程管理費」「肆、空氣污染防制費」「伍、抽檢費用」（第77-80項）
   以及「十二、工程品質管理費」~「十五、營業稅」（第73-76項）這8個合法編號的類別
   完全沒被偵測到（因為它們本身就帶數量/單價，不是純標題列）。這正是先前需要寫死
   「前76項」這個假設的根本原因。新版改成不論欄位型態，只要「項次」欄出現在編號
   清單裡就算數，並且每個類別的金額一律用「該範圍內工項複價自行加總」，不信任
   PCCES檔案本身印的小計數字，算不起來會印警告而不是默默吃掉。
   **驗證**：用您的真實檔案跑出的大項/中項金額加總 = 18,000,000元，與PCCES檔案
   的契約總價完全一致（零誤差），且無警告訊息，畫面截圖已核對「施工進度統計」表格
   確實正確列出全部20個大項/中項（含先前缺漏的貳參肆伍與十二~十五）。

2. **自動選分頁邏輯選錯分頁**：第一版寫的「自動偵測分頁」邏輯只看A欄是否出現
   「項次」兩字，但您的PCCES檔案裡「預算總表」（彙總頁，只有金額沒有單價數量）
   剛好也在A欄有「項 次」字樣，導致程式誤選到彙總頁、讀出0筆工項而報錯。
   已修正為同時檢查「單位/數量/單價」三欄是否也有對應標籤，只有真正的「詳細價目表」
   分頁才會通過。**驗證**：改完後用真實檔案重新測試，正確選到「預算詳細表」分頁，
   80個工項全數讀出。

## 更新記錄：2026-08-24 修正「契約總價算錯」的bug

您實際拿中興嶺案的契約書檔案（`(契約書)中興嶺調整池新建工程(第二次修正)...ap_cnt.xls`）

**問題**：舊版邏輯只信任文字裡「有+號」的總價列（例如「總價(壹+貳+參+肆+伍)」），找不到
就直接把全部工項複價自行加總當契約總價。中興嶺這份契約書裡，「壹、發包工作費」結束後
的總價列文字是「總價(總計)」（沒有+號），所以沒被信任，程式改成自行加總全部242個工項，
把後面獨立的「參、剩餘價值折價費」（-594,099元，一種土方餘方的扣款/調整項目）也一起
加了進去，算出115,605,901元。**已用您資料夾裡的「1150807-中興嶺調整池第十一次估驗」
真實請款文件核對，該文件E5儲存格明確寫著「契約金額：116,200,000元整」**，證實116,200,000
才是正確數字，「參」是契約金額之外的另計項目，不該被算進去。

**修正**：改成優先找「有+號」的總價列，找不到就改用文件裡「最後一筆」總價列（中興嶺案裡
就是「總價(總計)」=116,200,000），兩種都找不到才退回自行加總。不論用哪一種，都會把

寫在儀表板分頁最上方的說明文字裡。如果之後您需要「每個工項有各自獨立的預定進度」（而
不是共用同一條S曲線），需要另外擴充「預定進度」分頁的資料結構，是更大的功能，目前
還沒實作，有需要可以再提出。

  會被當成「舊項目刪除+新項目新增」，需要人工複核（這是先前版本就已知的邊界，這次沒有解決，
  只是把它明確標示出來，並確保這種情況下資料不會憑空消失）。
- 找不到對應新工項的舊工項：不會被丟棄，改整理進新增的「已刪除工項歷史記錄」分頁，保留累計
  完成數量與最後填報第幾天供歷史查核，不再參與後續進度計算——這樣就補上了先前版本「尚未支援
  刪除項目」的缺口，同時保證絕不悄悄遺失資料。
- 天數：預設完全沿用舊檔案「已建立的天數」不變；若指定了天數或展延日期，絕不會小於舊檔案
  已建立的天數（避免不小心把已填資料截斷遺失，會自動延長並在警告訊息說明）。
- 整個比對/還原機制完全靠掃描活頁簿裡的欄位標籤文字與相對順序自行定位，**不依賴外部
  `_meta.json` 側車檔案**——即使使用者手上只有單一份.xlsx（meta.json弄丟了）也能正常運作。
